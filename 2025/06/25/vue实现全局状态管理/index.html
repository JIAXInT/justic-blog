Vue 实现轻量级全局状态管理

背景

在 Vue 项目开发中，全局状态管理是一个常见需求。虽然 Vuex 和 Pinia 等专业库提供了强大的功能，但在一些小型项目中，如果对打包体积有严格要求，我们可能希望避免引入这些第三方依赖。本文将探讨如何利用 Vue 自身的特性实现一个简洁高效的全局状态管理方案。

这确保了无论在哪个组件中调用useCounterStore，都会获得同一个状态实例，实现了全局状态共享。

effectScope API 解析

effectScope是 Vue 3.2 版本引入的一个新 API，它的主要作用是创建一个”效果范围”，可以捕获在其中创建的响应式效果（如计算属性、侦听器等），并在需要时将它们一起处理。

scope.run()方法有两个关键特性：

  1. 它执行传入的函数，并返回函数的返回值
  2. 它自动捕获在函数执行过程中创建的所有响应式效果

effectScope(true)中的true参数表示创建一个分离的效果范围，它不会被父级范围自动收集。这对于状态管理特别有用，因为我们希望 store 的生命周期独立于使用它的组件。

在状态管理中的应用

在这个实现中，scope.run(fn)执行我们的 store 工厂函数，并捕获所有在函数内部创建的响应式效果。这意味着：

  1. 如果 store 中使用了computed、watch等响应式 API，它们会被自动捕获
  2. 即使没有组件引用这个 store，响应式系统也能正常工作
  3. 如果需要，我们可以通过调用scope.stop()来停止所有响应式效果，释放资源

使用effectScope的优势在于：

  • 可以统一管理 store 中创建的所有响应式效果（计算属性、侦听器等）
  • 在需要时可以统一清理这些效果，防止内存泄漏
  • 更好地支持 SSR 场景

总结

通过本文的实现，我们可以在小型项目中实现一个不依赖第三方库的全局状态管理方案。这种方案具有以下优势：

  1. 极小的代码体积
  2. 与 Vue 3 的组合式 API 完美融合
  3. 简单易用，概念少，学习成本低
  4. 自主可控，便于按需扩展

对于大多数中小型 Vue 项目来说，这种轻量级状态管理方案已经足够应对日常开发需求。当然，随着项目规模和复杂度的增加，我们依然可以考虑迁移到 Pinia 等专业状态管理库。
